Vouch

Unsecured credit lines, underwritten inside a sealed enclave.

A wallet's private financial history is scored inside a hardware-sealed enclave — never on-chain. Only the verdict becomes public: address, credit limit, expiry. That's enough for anyone to borrow FXRP with zero collateral.

In plain terms: Vouch lets a crypto wallet prove it's creditworthy without exposing the data that proves it — so lending protocols on Flare can offer real credit lines instead of forcing everyone to over-collateralize.

Why this needs to exist

Blockchains Can't
Trust What They
Can't See

Today, lending on Flare (and most of crypto) requires putting up more collateral than you're borrowing — because the chain has zero information about who's asking. Vouch gives it a verifiable answer without ever handing over the underlying data.

Today — XRPFi Lending
$12,000deposited as collateral
→ borrow only $8,000

Overcollateralized by design. The protocol can't assess risk, so it eliminates risk by demanding more value locked up than it lends out.

With Vouch
$0deposited as collateral
→ borrow up to your credit limit

The enclave's signed attestation stands in for collateral. Underwriting stays private; the result is public and verifiable by anyone.

Under the hood

How It Works,
In Six Steps

The entire loop — from private data to an on-chain loan — runs from a browser tab. No local process, no server the user has to trust blindly.

1
Your data stays in your browser
Persona / transaction-history data is held client-side and encrypted (ECIES) before it goes anywhere.
2
An underwriting request is sent
The encrypted data is passed to the rule engine for scoring — not to a database, not to a company server.
3
A sealed enclave scores it
A deterministic, versioned rule runs inside Flare Confidential Compute — a hardware-isolated environment nobody, including the operators, can see inside. The rule exists as byte-identical Go and TypeScript implementations.
4
The enclave signs a verdict
Output is a signed result: { address, creditLimitUsd, ruleVersion, expiry, signature } — nothing else leaves the enclave.
5
The chain checks who signed it
VouchCreditLine.submitResult() verifies the signature against the currently attested signer on-chain, and rejects anything else with "unattested underwriter".
6
The wallet borrows — no collateral
VouchPool.borrow() / repay() let the wallet draw FXRP up to its limit, USD-converted using a live FTSOv2 XRP/USD price feed.
The part judges actually need

Real vs. Simulated
vs. Curated

Instead of asking you to take it on faith, the project draws this line explicitly — and the UI labels it, too. Here's the honest breakdown.

Real
  • A real unsecured borrow (zero collateral posted) and its matching repay ran on the live pool — 0x04dae5…fd123 / 0x9d27c4…2dda.
  • The pool holds real FXRP (~49), priced by the live FTSOv2 feed.
  • VouchCreditLine verifies every signature on-chain and rejects a tampered rule build with a named revert — unattested underwriter.
  • The rule engine is byte-for-byte identical between Go and TypeScript (make verify line 1).
  • All three contracts are source-verified on the Coston2 explorer.
Simulated
  • Exactly one thing: the hardware attestation dispatch step.
  • Flare's own dev scaffold supports SIMULATED_TEE=true for this purpose.
  • The real FCC/FTDC dispatch path is blocked by an upstream availability-check timeout — a provider-side issue several teams hit during the event, not a bug in this project's code.
A same-mechanism mock-TEE fallback signs results with an identical rule engine and signature scheme. VouchCreditLine judges who signed — never how the result arrived — so switching to live dispatch is a config change, not a rebuild.
Curated
  • Demo data is three curated financial histories (personas.json) — not a live bank connection.
  • Clearly labeled as such inside the app UI, not hidden in fine print.
Don't take our word for it

Verify It Yourself

One command, three checks, each an independent MATCH / NO MATCH. Runs from a fresh clone — no .env file, public endpoints only.

terminal — make verify
$ make verify vouch verify — app: https://vouch-flare.vercel.app · chain: Coston2 MATCH rule equivalence Go engine == deployed app for all 3 personas (rule v1): thin-file-freelancer=$2088 salaried-employee=$6872 overindebted=$0 MATCH signer binding app signs as 0xc78e8d01e38149f0c7ac6018f0300aa636f32b83 == VouchCreditLine.attestedSigner() on Coston2 MATCH reject proof tampered-build signature reverts: "unattested underwriter" All 3 checks MATCH — what the demo shows is what the chain enforces.

Requires go, cast (Foundry), curl, python3. What this command deliberately does not verify (the Go image hash) is explained in extension/README.md.

Why it matters
